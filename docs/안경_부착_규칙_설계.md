# 안경 부착 규칙 설계

## 1. 목적

이 문서는 `glasses` 카테고리 액세서리를 아바타 얼굴에 부착할 때 사용하는 일반화된 배치 규칙을 정리한다.

목표는 특정 샘플 이미지 하나에 맞춘 수치 튜닝이 아니라, 서로 다른 안경 GLB와 서로 다른 아바타 head 비율에도 견딜 수 있는 **head-relative placement policy**를 정의하는 것이다.

이 규칙은 다음 용도로 재사용한다.

- feasibility 3D attach render
- preset 등록 전 검수 preview
- 향후 runtime accessory attachment

## 2. 설계 원칙

안경 부착은 고정 `offset/scale`만으로 맞추지 않는다. 아래 세 원칙을 따른다.

1. 크기는 `head` 기준 상대 비율로 계산한다.
2. 앞/뒤 축 방향은 단일 가정을 두지 않고 후보를 비교한다.
3. 최종 선택은 world-space 직감이 아니라 screen-space 결과를 점수화해서 결정한다.

즉, 안경 규칙은 `고정값 배치`가 아니라 `후보 생성 -> 점수 계산 -> 최고점 선택` 구조다.

## 3. 입력

### 3.1 spec 입력

`attachment_spec.json`의 기존 필드는 유지한다.

- `category`
- `anchorBone`
- `scale`
- `rotation`
- `offset`
- `cameraView`

이 중 `scale`과 `offset`은 최종 절대값이 아니라 **base placement 입력값**으로 해석한다.

### 3.2 runtime 입력

renderer는 다음 값을 추가로 계산한다.

- `head bone world transform`
- `head bounds world`
- `accessory local bounds`
- `camera`
- `viewport size`

## 4. Head 기준 참조값

안경 규칙의 기준 공간은 asset 공간이 아니라 `head` 기준 공간이다.

### 4.1 head metrics

`head` bone 또는 head 주변 mesh 기준으로 다음 값을 계산한다.

- `headBoundsWorld`
- `headWidth`
- `headHeight`
- `headDepth`
- `headCenterWorld`

### 4.1.1 head bounds source 우선순위

`headBoundsWorld`는 아무 mesh나 쓰지 않고 다음 우선순위로 계산한다.

1. VRM humanoid `head` bone 하위 descendant 중 실제 mesh가 존재하는 경우, 그 하위 mesh들의 world bounds
2. 위가 비어 있으면 `head` bone 기준 반경 제한 descendant mesh bounds
3. 그것도 비어 있으면 `head` bone world position만 사용하고, `headWidth/headHeight/headDepth`는 fallback 기본값 사용

fallback 기본값:

- `fallbackHeadWidth = 0.20`
- `fallbackHeadHeight = 0.24`
- `fallbackHeadDepth = 0.20`

이 fallback은 설계 실패를 숨기기 위한 것이 아니라, candidate 평가를 계속할 수 있게 하는 최소값이다.

### 4.2 eye line 추정

정밀 landmark는 사용하지 않고 head 높이 비율로 eye line을 추정한다.

- `eyeLineY = headMinY + headHeight * 0.60`

초기 기본값은 `0.60`으로 둔다.

### 4.3 render target

카메라는 accessory가 아니라 head 기준으로 고정한다.

- `renderTarget.x = headCenterWorld.x`
- `renderTarget.y = eyeLineY`
- `renderTarget.z = headCenterWorld.z`

`renderTargetSource`는 항상 `head_eye_line`으로 기록한다.

이 규칙을 쓰는 이유는 accessory를 따라가면 잘못된 depth 후보도 화면 중앙에 잡혀서 비교가 흐려지기 때문이다.

## 5. 크기 규칙

안경 크기는 절대 상수로 두지 않고 `headWidth`를 기준으로 계산한다.

### 5.1 asset size

accessory local bounds에서 다음 값을 계산한다.

- `assetWidth`
- `assetHeight`
- `assetDepth`
- `assetCenter`

### 5.2 target width

목표 안경 폭은 얼굴 폭의 비율로 계산한다.

- `targetGlassesWidth = headWidth * 0.78`

초기 기본값:

- `widthRatio = 0.78`

초기 허용 범위:

- `0.68 ~ 0.90`

### 5.3 scale 계산

- `baseScale = spec.scale`
- `autoFitScale = clamp(targetGlassesWidth / max(assetWidth, 1e-6), 0.05, 4.0)`
- `finalScale = baseScale * autoFitScale`

## 6. Pivot / Front Axis 후보

안경마다 앞면 축이 다를 수 있으므로 단일 `frontZ` 가정을 두지 않는다.

### 6.1 recenter 후보

두 가지 front plane 후보를 만든다.

- `frontPlaneMode = maxZ`
- `frontPlaneMode = minZ`

공통 center 계산:

- `centerX = (minX + maxX) / 2`
- `centerY = (minY + maxY) / 2`

후보 A:

- `recenterOffset = [-centerX, -centerY, -maxZ]`

후보 B:

- `recenterOffset = [-centerX, -centerY, -minZ]`

### 6.2 z forward 부호 후보

각 recenter 후보에 대해 전방 부호를 두 개 둔다.

- `forwardSign = +1`
- `forwardSign = -1`

즉 총 후보 수는 `2 x 2 = 4`개다.

## 7. 최종 배치 후보 생성

각 후보는 다음 구조를 사용한다.

- `placementRoot`
- `normalizedRoot`
- `accessoryRoot`

적용 순서:

1. `accessoryRoot.position = recenterOffset`
2. `normalizedRoot.scale = finalScale`
3. `placementRoot.rotation = spec.rotation`
4. `placementRoot.position = finalOffset`

### 7.1 final offset 규칙

`finalOffset`은 고정 literal이 아니라 head-relative 값으로 계산한다.

- `offsetX = 0`
- `offsetY = spec.offset.y`
- `offsetZ = forwardSign * (headDepth * 0.18)`

초기 기본값:

- `depthRatio = 0.18`

초기 허용 범위:

- `0.14 ~ 0.24`

최종 결합:

- `finalOffset = [spec.offset.x, spec.offset.y, offsetZ]`

이 단계에서는 `spec.offset`을 유지하되, `z`만 front candidate에 맞게 재해석한다.

### 7.2 초기 구현의 탐색 범위

초기 구현에서는 후보 공간을 아래처럼 고정한다.

- `frontPlaneMode in {maxZ, minZ}`
- `forwardSign in {+1, -1}`
- `widthRatio = 0.78`
- `depthRatio = 0.18`

즉 첫 버전은 4개 후보만 비교한다.

이후 일반화가 더 필요하면 `widthRatio/depthRatio`를 2~3개씩 더 열어서 확장한다.

## 8. 후보 평가 규칙

후보 4개를 모두 계산한 뒤 screen-space 기준으로 점수를 매긴다.

### 8.1 후보별 필수 계산값

- `projectedBBox`
- `projectedAreaRatio`
- `projectedCenterX`
- `projectedCenterY`
- `projectedWidth`
- `projectedHeight`
- `candidateWorldCenter`
- `anchorWorldPosition`

또한 head target도 projection해서 다음 값을 얻는다.

- `targetScreenX`
- `targetScreenY`
- `headProjectedWidth`

### 8.2 hard reject

다음 후보는 바로 탈락한다.

- `inFrame != true`
- `projectedBBox.height < 10`
- `projectedBBox.width < 40`
- `projectedAreaRatio <= 0`
- 화면 밖 대부분에 걸쳐서 bbox가 무의미한 경우

### 8.3 score 항목

#### centerX score

안경 중심이 얼굴 중심 x와 가까울수록 좋다.

- `centerXError = abs(projectedCenterX - targetScreenX)`
- 가중치 `0.30`

#### centerY score

안경 중심이 eye line 근처일수록 좋다.

- `centerYError = abs(projectedCenterY - targetScreenY)`
- 가중치 `0.30`

#### width fit score

안경 projected width가 얼굴 projected width 대비 적정 비율이면 좋다.

- 목표 비율: `0.72`
- 허용 범위: `0.55 ~ 0.90`
- 가중치 `0.20`

#### area fit score

너무 크거나 작지 않으면 좋다.

- 허용 범위: `0.005 ~ 0.035`
- 가중치 `0.10`

#### depth/front visibility score

anchor보다 얼굴 앞쪽에 있는 후보에 가점을 준다.

- 카메라 방향 기준으로 face front에 있을수록 유리
- 가중치 `0.10`

### 8.4 tie-break 규칙

score가 같거나 매우 가까운 후보는 다음 우선순위로 결정한다.

1. `centerYError`가 더 작은 후보
2. `centerXError`가 더 작은 후보
3. `frontPlaneMode = minZ` 후보 우선
4. `forwardSign = -1` 후보 우선

같은 입력에서 선택 결과가 매번 달라지지 않도록, tie-break는 반드시 deterministic해야 한다.

### 8.5 후보 선택 시점

후보 생성과 점수 계산은 매 프레임 수행하지 않는다.

원칙:

- 모델 로드 완료
- anchor resolve 완료
- head bounds 계산 완료
- 카메라 target 고정 완료

이 시점에 1회 계산하고 선택 결과를 고정한다.

이후에는 그 선택 결과를 그대로 렌더하고, `render_result.json`만 갱신한다.

이 규칙이 없는 경우 Fast Refresh, 카메라 미세 변화, floating point 차이로 후보가 프레임마다 바뀌는 문제가 생길 수 있다.

## 9. 최종 선택 규칙

- hard reject가 아닌 후보만 점수 계산
- 최고 점수 후보 1개 선택
- 선택된 후보만 실제 placement 결과로 사용

기록 필드:

- `selectedCandidateIndex`
- `selectedFrontPlaneMode`
- `selectedForwardSign`
- `selectedScore`

후보 전체는 `placementCandidates[]`에 기록한다.

각 후보 기록값:

- `frontPlaneMode`
- `forwardSign`
- `recenterOffset`
- `finalOffset`
- `baseScale`
- `autoFitScale`
- `finalScale`
- `projectedBBox`
- `projectedAreaRatio`
- `worldCenter`
- `score`
- `rejected`
- `rejectReason`

### 9.1 선택 실패 규칙

후보 4개가 모두 hard reject면 `glasses placement selection failed`로 처리한다.

이 경우:

- 임의 후보를 강제로 적용하지 않는다
- `render_result.json.ok = false`로 내리지 않고
- `warnings`에 `no_valid_glasses_candidate`를 남기고
- best-effort preview가 필요하면 가장 reject reason이 약한 후보를 debug 용도로만 렌더할 수 있다

단 feasibility pass/fail 판정은 이 상태를 성공으로 보지 않는다.

## 10. 결과 JSON 규칙

`render_result.json`에는 기존 필드를 유지하면서 아래를 추가한다.

### 10.1 top-level

- `headBounds`
- `headSize`
- `headCenterWorld`
- `eyeLineY`
- `renderTarget`
- `renderTargetSource`
- `selectedCandidateIndex`
- `selectedFrontPlaneMode`
- `selectedForwardSign`
- `selectedScore`

### 10.2 candidate list

- `placementCandidates: []`

각 후보는 9장의 필드를 그대로 가진다.

### 10.3 debug 해석용 필드

후속 튜닝과 실패 분석을 위해 아래 필드를 함께 둔다.

- `headBoundsSource`
- `headProjectedWidth`
- `targetScreenX`
- `targetScreenY`
- `selectedCandidateRejectMargin`

`selectedCandidateRejectMargin`은 선택 후보와 차점 후보의 score 차이로 정의한다.
이 값이 너무 작으면 rule이 아직 불안정하다는 뜻이다.

## 11. 이번 단계에서 바꾸지 않는 것

다음은 이번 규칙 문서 범위 밖이다.

- Python `attachment_spec.json` schema 변경
- hair accessory 정책
- landmark 기반 얼굴 정밀 분석
- 최종 runtime UI 편집 규칙

즉 이 문서는 `glasses` 카테고리의 renderer placement policy만 다룬다.

## 11.1 명시적으로 제외하는 것

아래는 이번 규칙이 다루지 않는다.

- 투명/반투명 렌즈 재질 문제
- 안경 다리(temple)와 귀의 정확한 접촉 판정
- 정밀 facial landmark 기반 코받침 정렬
- side-view 최적화

즉 이 정책의 목표는 `정면 MVP 기준으로 쓸 만한 위치`를 찾는 것이다.

## 12. 수용 기준

`glasses_only_001` 기준으로 최소 아래를 만족해야 한다.

- 안경이 화면에 실제로 보여야 한다
- 눈선 근처에 위치해야 한다
- 얼굴 폭 대비 과도하게 크지 않아야 한다
- 후보 4개 중 score 최고인 후보가 선택돼야 한다
- `render_result.json`만 보고 왜 그 후보가 선택됐는지 해석 가능해야 한다

## 13. 구현 순서

1. `headBounds`, `headProjectedWidth`, `eyeLineY` 계산
2. `renderTarget = head_eye_line` 고정
3. `frontPlaneMode x forwardSign` 4개 후보 생성
4. 후보별 projection 및 score 계산
5. 최고 score 후보 선택
6. `render_result.json`에 후보별 로그 저장
7. `glasses_only_001`로 검증

## 14. 현재 구현과의 관계

현재 renderer는 다음 단계까지는 도달했다.

- 3D attach render 실행
- head bone resolve
- scale/recenter/offset 단일 휴리스틱 적용
- world bounds / target / anchor 로그 기록

하지만 현재 방식은 단일 z축 가정과 단일 offset에 의존한다. 이 문서는 그 단일 휴리스틱을 후보 기반 일반 규칙으로 교체하기 위한 기준 문서다.
